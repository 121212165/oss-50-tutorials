## 它是什么（30 秒版）

Kanban 插件（4.5k+ star）在 Obsidian 里创建"Markdown 驱动的看板"：一个 .md 文件，打开时被渲染成可拖拽的看板列和卡片，卡片本身就是 Markdown 列表项，可以双击切回源码直接编辑。它证明了 Obsidian 插件里最酷的一种形态——**同一个文件、两种视图、永远以纯文本为准**。

## 为什么对你超有帮助

第一是直接使用价值：你的选题流程天然是看板——"灵感 → 已拆书 → 开头验证 → 连更中 → 完本"，一本小说一个卡片在列间拖动，而卡片背面用 Dataview 语法挂着字数和状态。第二是开发价值（写这篇的重点）：Kanban 是你学习"**自定义 View 类插件**"的最佳样本。你已有的插件大多是命令 + 设置页 + Notice 的"轻形态"，而 qs8-panel、story-ledger 想做成真正的面板，就必须掌握 ItemView 注册、视图状态管理、以及"视图修改数据 → 写回文件 → 触发重建渲染"这条闭环。Kanban 代码量适中（比 Excalidraw 小一个数量级），一天能读完主干，是比 Excalidraw 更合适的入门教材。另外它正在公开招募维护者（README 顶部就是），如果你想把"维护一个知名开源插件"写进开发者履历，这是个真实的机会——你这个水平完全接得住。

## 架构拆解

四个核心部件：

①**文件协议**：看板文件本质是 Markdown，列 = `## 列名` 标题，卡片 = 列标题下的无序列表项，卡片附注用 `%%注释%%` 存元数据（比如日期、完成时间）。这个设计让看板与其他插件（Dataview 查询、Git 备份）天然兼容。

②**View 注册**：插件用 `registerView(VIEW_TYPE, ...)` 告诉 Obsidian"打开 .md 看板文件时用我的渲染器而不是默认编辑器"，通过 `onExternalSettingsChange`/元数据判断文件类型。这是视图类插件最关键的一步。

③**双向同步**：用户在 UI 上拖卡片 → 更新内存状态 → 序列化回 Markdown 写入文件；反过来用户在源码模式改了文本 → 文件变更事件触发 → 重新解析 → 更新 UI。所有"UI 状态 vs 文件状态"冲突问题（光标丢失、循环触发）它都踩过并解决了，源码里这套防抖和比较逻辑值得精读。

④**卡片交互**：日期选择器、进度条、拖拽排序，全部构建在原生 DOM + Obsidian API 上，没有引入重型前端框架。

## 上手路径

第一步：市场安装 Kanban，新建"看板"笔记，切到看板模式。第二步：建"灵感/拆书中/连更中/完本"四列，把手上几本书填成卡片。第三步：给一张卡片加日期（右键菜单），观察它在 Markdown 源码里变成了 `@{2026-09-28}` 这样的标注——这就是它的元数据编码方式。第四步：切源码模式手动加一行卡片，切回看板确认出现。第五步：想深入源码的话，从 `src/Settings` 和 View 入口两个文件读起。

## 进阶玩法 / 避坑

避坑一：卡片正文里不要放复杂嵌套语法，看板渲染器对嵌套支持有限，复杂的进卡片附注。避坑二：它的看板文件被其他插件同时写入时（比如自动同步插件）可能出现合并冲突，同步间隔别设太短。进阶：把它当模板，给你自己的"扫榜选题流水线"做一个定制看板插件——列固定为你的四层降级链路，卡片拖到"已验证"列时自动触发你的扫描脚本打分，这是视图类插件最好的练手项目。

## 横向对比：为什么是这个不是别的

项目管理工具宇宙里（Trello、Notion、Linear……），Kanban 插件的差异化只有一个但足够狠：数据就在你的 Markdown 里。Trello 停服你的板子就没了，Markdown 看板永久可读可查可被任何工具消费——数据主权，是本地优先软件的终极卖点。

## 认知红利：这篇能改变你什么

它证明了"UI 只是数据的视图"可以做到多彻底：拖拽卡片，落盘的是文本；改文本，界面自动跟上。写任何带界面的工具时，先问自己"我的数据格式能不能脱离这个界面独立存在"——能，工具就永远不会绑架用户。
