## 它是什么（30 秒版）

MetaGPT（7 万 star，MIT，中文团队主导的明星项目）的核心创意：**把软件公司的 SOP（标准作业程序）编码进多 Agent 框架**——输入一句话需求，"产品经理"Agent 写 PRD，"架构师"画设计，"工程师"分工写代码，像一条流水线一样产出完整项目。它的口号是给 GPT 分配不同角色组成协作实体。作者后来把它产品化成了 MGX（mgx.dev），2025 年冲上 Product Hunt 周榜第一，学术侧的 AFlow（自动生成 Agent 工作流）也拿了 ICLR 2025 Oral。

## 为什么对你超有帮助

对非程序场景的最大启发：**SOP 是比模型更重要的资产**。MetaGPT 的本质洞察是——把人类组织的流程规范（谁在什么阶段交付什么格式的什么产物）写成 Agent 的行为约束，产出质量就会稳定。这恰好是你规则沉淀引擎的底层哲学：你已经在做"把审稿经验沉淀成规则 v1"，MetaGPT 把这条路走到了框架级。三个可搬走的点：①**中间产物结构化**：它的每个角色交付的是标准格式文档（PRD 表、接口定义），不是自由文本——你的管线里"上一环节交给下一环节"的东西也应该是结构化台账而不是聊天记录；②**角色 = 提示词 + 输入输出契约**：一个 Agent 的稳定性不靠聪明，靠契约写得死——审稿引擎每个环节都该有 expected_output；③**学术跟随**：它团队的工作流自动生成（AFlow）方向，预示"管线自动优化"会是你这类内容生产系统的下一步，先建立概念地图。另外它中文文档友好（README 就有中文版），阅读成本低。

## 架构拆解

四层结构：①**角色层（Roles）**：每个 Role 绑定 system prompt、可用的 Action 列表、观察什么消息、发布什么消息——本质是"提示词 + 订阅关系"；②**动作层（Actions）**：最小执行单元，一个 Action = 一次带结构化输入输出的模型调用（比如 WritePRD、WriteCode、RunCode）；③**环境层（Environment）**：消息总线，Role 之间通过"发布/订阅"消息协作，谁完成动作、广播什么，其他角色决定要不要响应——这是它区别于流水线的地方，协作图是动态的；④**SOP 编排**：预置的流程定义（需求 → PRD → 设计 → 编码）约束消息流转，用户可以自定义 SOP。执行入口一行：`startup` 命令或 `MetaGPT().run("需求描述")`。拆完你会发现：MetaGPT 的"公司"其实是**发布订阅消息系统 + 结构化动作图**，去掉拟人化包装后是一个非常干净的架构。

## 上手路径

第一步：`pip install metagpt`（版本要求见官方文档，建议独立环境），配好 key。第二步：`metagpt "做一个记账小工具的命令行版本"`，围观 PRD → 设计 → 代码的完整产出链。第三步：读输出目录里的结构化中间产物，体会"每步交付物"的价值。第四步：进阶玩法换战场——用它的 Role/Action 抽象定义你的"写作公司"：策划出选题卡、写手出章稿、审稿出评分单，SOP 换成你的生产流程。

## 进阶玩法 / 避坑

避坑一：MetaGPT 社区热度已过峰值，代码跟进不如前几年活跃，生产环境选型建议 LangGraph/MAF，把它当"思想教材 + SOP 架构参照"。避坑二：完整软件公司流程 token 消耗大，先跑小需求试水，顺便用你的 agent-quota 记录消耗——顺手给自己的框架做一次成本实测。进阶：把它的 PRD 模板思想用在"书开题"上：写一份《开题 PRD》（卖点、人群、雷点、爽点节拍），再交给写手 Agent——流程的仪式感会真实地提升开题质量。

## 横向对比：为什么是这个不是别的

MetaGPT 与其说是框架，不如说是"方法论论文的可执行版"——同样是多 Agent，AutoGen 们回答"怎么协作"，MetaGPT 回答"协作要有 SOP"。热度已过峰值，但作为思想样本它反而是更纯粹的一个：当你要向别人解释"为什么你的写作管线要分环节、定交付物"，引用 MetaGPT 比引用任何新框架都更有说服力。

## 认知红利：这篇能改变你什么

"中间产物结构化"是它最值得内化的一条：角色之间传递的不是聊天记录，而是标准格式的文档。你的管线里，上一环节交给下一环节的也应该是"开题卡、评分单、修改清单"这种契约物——聊天气泡是噪音，契约是资产。

> 冷知识：MetaGPT 团队的 AFlow 论文拿了 ICLR 2025 Oral（LLM Agent 方向第二名）——"自动优化工作流"是它的学术后手，也预示你的管线终将进入"自动调优"阶段。
