## 它是什么（30 秒版）

Mermaid（9 万 star）让你用 Markdown 风格的文本生成图表：流程图、时序图、甘特图、类图、状态图、思维导图等——写在 \`\`\`mermaid 代码块里，渲染即成图。GitHub/GitLab 原生支持渲染，Obsidian 直接可用，还有官方 Live Editor（mermaid.live）在线写。口号一句话：diagrams-as-code，图也可以进版本管理。

## 为什么对你超有帮助

你的日常大量产出"结构化解释"——拆解报告、管线文档、README——而文字讲结构的效率远低于图。Mermaid 对你的三个精准命中：①**Obsidian 无缝集成**：你的笔记库里 \`\`\`mermaid 块直接渲染，审稿引擎数据流、五层重建计划这类文档配图零成本；②**图进 Git**：你是归档控，最恨"二进制资产改不了、diff 不了"——Mermaid 图是纯文本，Git 能 diff、能回滚、AI（包括你用的 Agent）能直接生成和修改——**Agent 时代画图的最优解就是它**，你说一句"把这个流程画成 mermaid 时序图"就能得到可版本化的图源；③**教程站当场用**：本站 50 篇教程里的流程都可以配 Mermaid 图，GitHub Pages 上原生渲染，无构建负担。你现有工具链里它已经无处不在（hello-algo 站点、OpenHands 文档都在用），现在把它变成你的主动技能。

## 架构拆解

理解三层：①**DSL（文本语法）**：每种图一种小语法——流程图 `graph TD; A[开始] --> B{判断}; B -->|是| C[处理]`，时序图 `sequenceDiagram` 下 actor 互发消息，箭头/节点形状/样式有约定俗成的记号；②**解析与布局引擎**：Mermaid 把文本解析成语法树，然后调用 **dagre-d3（DAG 有向图布局库）** 计算节点坐标——"布局自动化"是它与画图工具的本质区别：你只声明关系，坐标引擎负责好看；时序图、甘特图则各有专门布局器；③**渲染层**：产 SVG（矢量、可缩放、可无障碍阅读），嵌在 Markdown 渲染管线里随文档生成——所以 GitHub/Obsidian/静态站全兼容。语法心智提示：`-->` 实线箭头、`-.-` 虚线、`-->|标签|` 带边注、子图 subgraph 框分组——记住这四样能覆盖 80% 场景。

## 上手路径

第一步：打开 mermaid.live，左边敲右边看，从流程图开始画"你的审稿引擎流程"（收稿 → AI 味检测 → 评分 → 条件路由）。第二步：学时序图，画一次"插件 ↔ 主进程 ↔ 服务端"的消息往返（用你 Obsidian 插件的场景）。第三步：在 Obsidian 里建一页"系统地图.md"，用 subgraph 把你的写作系统五层架构画成一张总图。第四步：把两张图分别贴进本教程站对应教程和某个 GitHub README，验证跨平台渲染。

## 进阶玩法 / 避坑

避坑一：复杂大图（50+ 节点）布局会失控，Mermaid 适合中小结构图，巨型架构图分拆成多张或改用 Excalidraw 手工排版（第 50 篇正好衔接）。避坑二：节点文本里的特殊字符（括号、引号）要用引号包裹 `A["文本(带括号)"]`，这是最高频的报错原因。避坑三：GitHub 渲染的 Mermaid 版本落后于最新版，新语法（如 mindmap 早期版本）可能不显示，常用语法最安全。进阶：用 Mermaid 的 flowchart 表达你的采集决策树、用 journey 图做用户旅程拆解；再把" Mermaid 图源模板"沉淀进你的拆解方法论文档——从此你的每篇拆解都自带可维护的图，这就是"图表即文档"的完整落地。

## 横向对比：为什么是这个不是别的

画图工具分工表：Mermaid（代码生成、进文档进 Git）、Excalidraw（手绘思考、自由探索）、draw.io（精确排版、老牌万能）、PlantUML（UML 专家、语法古老）。组合拳是"探索用 Excalidraw，定稿转 Mermaid，复杂排版用 draw.io"——图和代码一样，不同阶段用不同工具。

## 认知红利：这篇能改变你什么

Mermaid 的本质贡献是"图进入了文本工作流"：可 diff、可版本化、可被 AI 生成。当画图不再需要鼠标，图的更新频率就追上了文档——你拆解文档的配图质量，从此只受限于表达欲，不受限于工具。
