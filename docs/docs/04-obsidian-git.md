## 它是什么（30 秒版）

Obsidian Git（12k+ star）把完整的 Git 能力搬进 Obsidian：定时自动 commit + pull + push、启动时自动拉取、源码管理面板（暂存/提交/对比差异）、历史记录浏览、编辑器内的行级修改标记。你的笔记库从此有了一份带完整版本历史的异地备份，而且全程无感。

## 为什么对你超有帮助

两个层面。实用层：你正在学 Git/GitHub，最好的学习方式就是让 Git 无处不在地替你干活。你的 obsidian-vault 笔记库（里面还有 WorkBuddy 灵感库和《戒梦百条》资产）现在就可以用它：设置"每 30 分钟自动 commit-and-sync"，从此写作素材永远有云端版本历史，再也不怕"磁盘原件已丢失"这种事故——你对这类事故的痛是有切身体会的（novel-bible-recovery 那次灾难恢复）。学习层：它是"把 CLI 工具包成 GUI 插件"的教科书。插件内部其实是用 child_process 调用系统里的 git 命令，再把输出解析成可视化面板。你以后想把 dsh、agent-quota 这类 CLI 工具做成带界面的产品，这套"命令行内核 + 视图层"的分层架构就是最短路径。

## 架构拆解

核心概念叫 **commit-and-sync**：一次操作串联"提交本地改动 → 拉取远端 → 推送远端"三步，这是它和普通 Git 客户端最大的区别——为单用户笔记库把 Git 的协作语义简化成了"同步"语义。拆开看五个模块：①调度器：按设定间隔（或文件变更防抖后）触发同步，启动时先 pull；②Git 执行层：封装 git 命令调用与错误处理；③Source Control View：列出变更文件，支持单文件暂存/撤销；④History/Diff View：读 git log 和 diff 输出渲染成面板；⑤编辑器标记（signs）：把 diff 结果映射回行号画标记，桌面端可用。移动端因为没法跑系统 git，走的是 isomorphic-git 的 JS 实现，所以 README 明确警告移动端"高度不稳定"——本地能力决定架构选型，这个教训通用。

## 上手路径

第一步：先在 GitHub 建一个**私有**仓库（笔记别公开），本地 `git init` 并关联远端。第二步：市场安装 Obsidian Git，启用后打开设置。第三步：设置 Auto commit-and-sync 间隔（建议 30 分钟，太频繁会让历史变成噪音）。第四步：手动点一次 "Commit-and-sync" 验证能推送成功——推送失败多半是没配好凭证，用 Git Credential Manager 登录一次即可。第五步：明天开电脑时检查 Obsidian 启动日志，确认"auto-pull on startup"生效，闭环完成。

## 进阶玩法 / 避坑

避坑一：`.obsidian/workspace.json` 这类会话状态文件每次打开都变，加进 `.gitignore`，否则每个 commit 全是垃圾差异。避坑二：大附件（录音、图片库）会让 Git 仓库膨胀，要么 exclusion 要么单独管理。进阶：试试它的编辑器内 diff 标记，对着修改看"哪些行是 AI 写的、哪些是你改的"，这对你的去 AI 味修改流程意外地好用；再读源码里 `src/ui` 与 git 调用层的边界划分，体会"视图永远不直接碰命令行"这个纪律。

## 横向对比：为什么是这个不是别的

笔记同步路线四大派：官方 Sync（付费省心）、iCloud/网盘（免费但易冲突损坏库）、Syncthing（点对点同步、不进版本管理）、obsidian-git（版本管理 + 云端）。restic（第 48 篇）管快照容灾，Git 管"每次改动的历史"，它们是互补关系——搞清楚这一点，你的数据安全矩阵才算配齐。

## 认知红利：这篇能改变你什么

它把"commit"从一个主动动作变成了后台行为——这个思路可迁移到你的所有系统：写作管线的台账、扫榜数据、审稿结果，都可以做"无感归档"。最好的持久化是用户（包括你自己）意识不到的那一种。

> 冷知识：这个插件在移动端其实换了一套引擎（isomorphic-git 纯 JS 实现），等于一个项目养了两条技术路线——为兼容性付出的双倍代价，商业产品里常见。
