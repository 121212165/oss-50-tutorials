## 它是什么（30 秒版）

f/prompts.chat 是提示词开源化的鼻祖之一，GitHub 星标十几万，是"awesome list"文化的代表作。核心就是一份 README/CSV：几百条精心写的角色化提示词（"你是 Linux 终端""你是面试官""你是旅行向导"），每条都以 `Act as ...` 开头，社区通过 PR 持续贡献。对今天更强的模型来说，部分 prompt 显得朴素，但它是学"提示词如何被大规模组织与维护"的最佳标本。

## 为什么对你超有帮助（结合你的具体项目说）

对你而言，价值不在"抄 prompt"，而在三点：

1. **prompt-vault 的模板范本**。你的提示词沉淀库最头疼的是格式不统一。这个仓库的解法值得抄：每条 prompt 一个固定字段（角色名、一句话描述、正文），集中在一个 CSV 里、由脚本生成 README。你的 vault 完全可以照搬：prompt + 适用模块（审稿/去味/扩写）+ 验证记录 三个字段强制填写。
2. **角色化写法的灵感库**。你的审稿引擎 v4 的 QS-8 维度，本质是让模型扮演"资深网文编辑"。这个仓库里 Act as an Editor、Act as a Journalist 之类的条目，可以横向对比它们各自的系统提示结构（职责定义 → 输出格式 → 约束条件），提炼出你自己的"编辑人格"模板。
3. **去 AI 味管线的对照素材**。大量条目是典型"AI 腔"的产物（过度结构化、bullet point 强迫症）。把它们跑一遍、记录套路化特征，负样本不用自己造。

## 架构拆解（核心模块 + 数据流）

仓库结构是"awesome list"的标准范式：

- **prompts.csv**：真正的单一数据源。每行一条 prompt，列包括 act（角色名）、prompt（正文）、for_developers（是否面向开发者）等。所有展示层都从它生成。
- **README.md**：面向人阅读的目录，按角色名字母排序，内嵌表格。历史上由脚本从 CSV 生成，保证"改一处、处处同步"。
- **应用层**：配套的 prompts.chat 网站提供搜索与一键复制；还有非官方的 ChatGPT-Plugins-Store、VSCode 扩展等衍生生态。
- **贡献流**：社区 PR 修改 CSV → 维护者审查是否符合格式（有 CONTRIBUTING 指南规定 prompt 写法）→ 脚本重建 README。

数据流一句话：CSV（源）→ 脚本 → README/网站（展示）。这就是最朴素的"内容即数据"工程，和你的 prompt-vault 思路同源。

## 上手路径（第一步做什么，命令级）

```bash
git clone https://github.com/f/prompts.chat.git
cd awesome-chatgpt-prompts
# 用 Excel/Obsidian 直接打开 prompts.csv，或命令行看前几行：
head prompts.csv
```

第一步：浏览 CSV，挑 5 条和写作相关的角色（editor、novelist 类），粘贴进你的模型跑一遍。第二步：用 Python/CSV 工具把其中结构最规整的 3 条改写成"网文审稿人"版本，存入 prompt-vault 并记录验证结果。第三步：模仿它的 CSV 字段设计，给你的 vault 定 schema。

## 进阶玩法 / 避坑

- **进阶**：写个小脚本把 CSV 里的 prompt 批量喂给模型，统计输出长度、句式、高频词分布，作为去 AI 味管线的"基线语料"；再给你的 vault 做一个同样的"CSV → Markdown 目录"生成器，一劳永逸。
- **避坑**：① 内容对最新模型偏过时，"Act as"前缀现在未必最优，重情境描述、轻角色扮演是当前趋势；② star 数量不代表单条 prompt 质量，社区贡献良莠不齐，务必自己验证；③ README 是生成产物，直接改 README 的 PR 会被拒——改 CSV 才是正确姿势；④ 中文使用者注意：原仓库全英文，中文 prompt 的语感规则（成语、节奏）不能直接套英文模板。

## 横向对比：为什么是这个不是别的

## 认知红利：这篇能改变你什么

它的"Act as X"句式曾经统治世界，如今效果平平——这个兴衰本身就是一课：提示词的最佳实践随模型代际更替，任何"永远有效的模板"都不存在。你的规则 v1 也一样，要标注"验证于什么模型、什么时间"，过期就该退役。
